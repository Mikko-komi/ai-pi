# 安全

Pi 是本地 coding agent。它以启动它的用户账户的权限运行，并把该用户可写的文件视为同一本地信任边界之内。

## 项目信任

项目信任控制 Pi 是否加载项目本地的设置、资源、软件包和扩展。它不是沙箱，也不会在你开始在某个目录工作之后，限制模型能让工具做什么。

从当前工作目录发现以下任一内容时，Pi 认为该项目包含需要信任的资源：

- `.pi/settings.json`
- `.pi/extensions`、`.pi/skills`、`.pi/prompts` 或 `.pi/themes`
- `.pi/SYSTEM.md` 或 `.pi/APPEND_SYSTEM.md`
- 当前目录或祖先目录中的项目 `.agents/skills`

空的 `.pi` 目录本身不算需要信任的项目资源。

交互式会话在带有需要信任的资源的项目中启动，且当前目录或父目录没有已保存的决定时，Pi 遵循全局设置中的 `defaultProjectTrust`。默认值是 `"ask"`：在 UI 可用时询问是否信任该项目。已保存的决定按规范化目录存在 `~/.pi/agent/trust.json`，当前路径或父路径上最近的已保存决定优先于全局默认值。

信任项目后，Pi 可以加载需要信任的项目资源，包括：

- `.pi/settings.json`
- `.pi` 资源，例如扩展、skills、提示词模板、主题和系统提示文件
- 通过项目设置配置、但尚未安装的项目软件包
- 项目本地扩展以及由项目软件包管理的扩展

拒绝信任则会跳过受保护资源。`AGENTS.override.md`、`AGENTS.md` 和 `CLAUDE.md` 等上下文文件无论项目信任与否都会加载，除非已禁用上下文加载。信任尚未决议之前，Pi 只加载上下文文件、用户/全局扩展，以及 CLI `-e` 扩展。用户/全局扩展和 CLI 扩展可以处理 `project_trust` 事件；第一个返回是/否决定的扩展拥有该决定。

非交互模式（`-p`、`--mode json` 和 `--mode rpc`）不会显示信任提示。若没有适用的已保存信任决定，`defaultProjectTrust: "ask"` 和 `"never"` 会忽略这些资源，而 `"always"` 会信任它们。用 `--approve`/`-a` 或 `--no-approve`/`-na` 可覆盖单次运行的项目信任。

## 没有内置沙箱

Pi 不包含内置沙箱。内置工具可以按 Pi 进程的权限读文件、写文件、编辑文件并运行 shell 命令。扩展是 TypeScript 模块，权限相同。软件包安装、shell 命令、语言服务器、测试命令以及其他开发工具，行为与普通本地进程一样。

这是有意设计。Pi 用于操作本地源码树、调用项目工具链，并接入用户现有的开发环境。进程内的部分沙箱很容易被误当成安全边界，同时仍然依赖宿主 shell、文件系统、包管理器、凭证和扩展代码。真正的隔离必须来自操作系统，或虚拟化/容器边界。

项目信任只是输入加载守卫。它阻止仓库在你批准之前悄悄改掉 Pi 的设置或扩展。它不会让不受信任的代码、不受信任的提示或不受信任的模型输出变得安全。来自仓库文件、注释、文档、上下文文件或构建输出的提示注入，是本地 agent 的预期风险，Pi 无法可靠地阻止。

## 运行不受信任或无人值守的工作

对于不受信任的仓库、你不打算紧密监控的生成代码，或无人值守的自动化，请在受控环境中运行 Pi。使用容器、虚拟机、微虚拟机、远程沙箱，或策略可控的沙箱，并且只提供任务所需的文件和凭证。

常见模式见[容器化](containerization.zh.md)：

- 把整个 `pi` 进程放进容器/沙箱
- 在宿主机运行 Pi，同时把内置工具的执行路由进 Gondolin 微虚拟机
- 只挂载 agent 应访问的工作区路径
- 除非容器需要访问宿主机的会话、设置和凭证，否则不要挂载宿主机的 `~/.pi/agent`
- 只传入最少所需的 API key，或使用短期凭证
- 任务不需要网络时限制网络访问
- 把结果复制回受信任系统之前，先审阅 diff 和输出

如果以读写方式绑定挂载宿主机工作区，容器或虚拟机内部的写入仍会修改宿主机文件。需要更强地防止意外写入时，请使用只读挂载，或把文件复制进沙箱再复制出来。

## 报告安全问题

要报告安全问题，请遵循仓库的[安全策略](https://github.com/earendil-works/pi/blob/main/SECURITY.md)。不要为安全敏感报告开公开 issue。

本地 agent 的预期行为、缺少内置沙箱、来自不受信任内容的提示注入，以及用户安装的扩展或 skills 的行为，一般不在安全边界内，除非报告证明了真实的权限边界绕过，或说明 Pi 授予了本地用户原本并不具备的访问权限。
